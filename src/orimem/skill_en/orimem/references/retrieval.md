# Knowledge recall

1. For known files and small local edits, read directly and in a targeted way. For a new task or a resumption lacking project background, use `task_context`(cwd, task_query, authorized_scope) to fetch bounded background by path, name and alias; it does not start the vector model or read the project. If valid project context already exists, reuse it. On a miss or ambiguity, use project and lesson navigation, and call `recall` once the scope is determined.
2. Parameters: query, scope (in-vault file or folder prefix, required), limit (1–12, default 6), mode (hybrid/lexical/semantic, default hybrid), include_history (default false), include_pending (default false), graph (default true). scope does not accept disk paths; full-text, vector, graph and evidence all obey the same scope.
3. Look at the short excerpt, heading, kind and evidence_id first. For useful results, call `evidence`(evidence_ids, scope, max_chars); the default budget is 12000 characters, at most 8 chunks. Evidence is bound to the source file hash; after the source changes, old IDs are rejected, so recall again.
4. Project status is taken only from the single current project page; historical material, snapshots and assistant reports keep their dates and verification scope. Graph expansion uses only explicit wikilinks, aliases and project/course properties; ambiguous links are not guessed, and authorization is not expanded.
5. If the current context already has valid evidence, reuse it. Query again only for a new question, a changed scope or stale evidence; stop once knowledge is sufficient. Read [history.md](history.md) only when there is a history gap. Without a hit, do not force-fit similar experience.

In Claude Code and dsh these tools appear as `mcp__orimem__task_context`, `mcp__orimem__recall`, `mcp__orimem__evidence`, etc.

A single local SQLite stores body text, FTS5, 384-dimensional E5 vectors, relations and sources; cosine and BM25 are fused with RRF. The model version is pinned, inference is offline, and no text is uploaded remotely.

`task_context` only reads the index and the one matched note; it does not load the backend or embeddings. The returned scope_advice is a scope suggestion and does not expand authorization; an explicit scope limits actual reads; status/next_action are source data, and paused execution is not resumed on that basis. Re-fetch when the version or task topic changes; do not treat background whose bytes do not match as reusable state.

Projects and other matters are initialized with `initialize` into `10 Projects`; courses are initialized into `15 Courses/<name>/Course Home.md`. Initialization keeps a single entry point, working-directory metadata and a writer receipt; repeated calls with no change write no body text and recompute no vectors; a different category or a working-directory conflict returns the conflict first and does not overwrite the original binding. Raw course materials are outside the automatic write scope.

Recall first filters scope and history kind in SQL, then reuses the bounded candidate matrix, vectors and query encoding for the current corpus/model version. Normal queries only check the current file hash for candidates that may be returned; when stale candidates are found, a full check and re-ranking are performed. Evidence reads still check the current body version; caches or file times cannot replace the evidence hash.

All stdio bridges share one on-demand local backend, so each chat does not reload the model. File events are debounced for 3 seconds with a 60-second reconciliation; after 30 minutes without requests it stops, and the next call reconciles again. Changes made while asleep or stopped are indexed after resuming; long-term unattended operation is not claimed to be verified.

Recent ordinary messages can explicitly join full-text and semantic fusion with include_pending=true. Staged messages are bound to the current project/course entry only through a unique cwd binding, with scope filtering performed before SQL candidates and full-text search; without a unique binding nothing is guessed, and they can still be read through authorized history pagination. Results are marked kind/source_state=pending, temporary=true, with source_key, current version, event_time and role; path denotes the authorized project entry point, not an exported session file. Neither assistant reports nor staged content are automatically turned into formal knowledge; do not use them to overwrite the single project page status.

A pending evidence_id can be fetched through the same `evidence`, returning the original message character offsets, event index and source hash; after the source, project binding or model changes, old evidence is rejected. The pending-index and source-index jobs on the same background database encode in batches and share the vector cache. Ordinary messages are continuously turned into stable transcripts by the projection job; the generated body text is not a second vector source.

With an explicit scope on a continuous transcript path or its authorized folder and include_history=true, unbound sources can be retrieved. kind=source returns message-level versions and source ranges; independent messages with identical text are not deduplicated into one; evidence for unchanged old messages is not all invalidated when the session is appended to. When program body changes conflict, evidence from the old projection is refused; manual annotations are not automatically overwritten. Scope must not be expanded by similarity or parent-chunk expansion. When recent compatibility pending and canonical sources are queried together, duplicate views are avoided by source identity; in health, saving, projection and indexing are accepted separately.

## Current basis, historical intent and full context

A note's explicit property `retrieval_basis: historical-only` means the body is kept as historical material and withdrawn from the current basis; it is not inferred from date, processed/draft status or similarity that the facts are wrong. current recall and direct evidence fetches are both blocked, even with include_history=true; historical can still read the same source text, returning retired-note-history/not_current_basis and the actual retirement record time. canonical/pending ordinary raw messages do not inherit this property from associated projects or organized drafts. Source hash and scope verification are kept; old evidence IDs must also be relocated after metadata changes.

`recall`/`evidence` support `time_intent=current|historical`, default current; it and include_history ("which evidence kinds to include") express different purposes. current filters explicitly corrected/pending-review assertions and registered historical sections; the historical source text is still kept. historical allows reading those original words with basis_status/correction_ids attached; historical intent cannot be used to lift scope or source-version verification. Known valid_from/valid_to and rule effective times take part in current applicability; unknown ones are not filled in.

Independent paragraphs within affected chunks can return safe evidence IDs, bound to the original source version and exact range; vectors still only rank candidates, and this cannot turn a paragraph into a factual relation. Old whole-chunk IDs containing assertions pending correction are refused for current. In a new conversation, a correction version from `task_context` invalidates the cache, so do a guarded recall/evidence first even if the note hash has not changed; version.freshness only proves byte freshness, and fact_validity separately reports pending review.

If an explicitly bound canonical raw message later changes version, an unreviewed new version does not automatically lift the old semantic correction because the bytes were updated; current does not adopt it for now, and historical returns corrected-origin-version-needs-review and not_current_basis. Source saving/projection keeps running; do not treat the evidence gate as message loss or as a decided error in new facts. Quoted blank lines in old snapshots are also delimited by source range; retracting a single example does not swallow an independent general method.

`evidence(...,expand=none|section|dialogue)` adds context within the same max_chars budget; every fragment has a source range/source version, and the main fragment and parent chunk do not take up space twice. section takes conditions from the same section or the owning question section; dialogue, within an old session snapshot bound by an explicit canonical source path or SHA, expands the same observed user turn, stopping at the next user message. It prefers returning at most 4 assistant messages at the end of that turn, to avoid getting only progress notes; beyond 4 it is marked partial-turn-limit, and the existing main fragment is kept. Neighboring/same observed turn is not proof of factual support, stable upstream identity or reply completion. Old snapshots use only the message headings, source ranges and file SHA of indexed body text; do not read back JSONL or old DB caches to replace user modifications.

Legacy pending only has workspace ownership and cannot use project scope to extend to other messages; an explicit source scope is required. When context_status carries partial-budget/partial-turn-limit, continue targeted evidence fetching; do not claim the whole turn is complete. When an old snapshot lacks a canonical dialogue section, has ambiguous headings, or its time or message range cannot be verified, report that it cannot be expanded; do not guess. Other notes and project scopes do not use dialogue to fetch cross-topic sources. Multiple IDs are still packed with deduplication by same source version/source range; the current correction filter applies to both the main fragment and expanded fragments.

A long correction message may quote the old conclusion in its first sentence and only negate it at the end. When the budget is sufficient, the registered correction quote is returned in full; when insufficient, requires_context/not_current_basis marks that the first fragment cannot be taken as reconfirmation. upstream_truncated is separate from budget truncated; Source context reports source_state/index_state separately for saving, projection and indexing.

This gate also applies to adjacent correction fragments in dialogue and to correction quotes of registered archive sources. Old snapshots are bound by file SHA/source range, continuous sources by message version; small-budget multi-ID packing lists complete correction context that does not fit under incomplete, and does not use its affirmative first sentence as a placeholder. Corrected exact targets continue to be withdrawn from current, and historical can still read the original words; corrections are not registered automatically based on turn adjacency.

## Knowledge representations and neighbor candidates

`lifecycle(action="knowledge_sync",arguments={scope:[exact knowledge path],limit:12})` explicitly registers deterministic section representations of selected knowledge; afterwards file reconciliation only maintains registered paths incrementally, and the persistent knowledge-index job reuses leases, bounded retries and the same vectors cache. Titles, questions, methods and applicability conditions use local E5; source hash tables and navigation templates are not read as topic semantics. It is a candidate-discovery layer and does not replace `recall`/`evidence` on specific chunks.

`knowledge_neighbors(path,scope,limit)` requires both the starting point and candidates to be within the explicit scope. It returns semantic_neighbor/candidate/requires_review, only hinting at potential duplicates, mixed topics or connections; similarity cannot prove correctness, factual relations, automatic merging or project ownership, and does not write wikilinks. First actually read the question, conditions and sources, then decide what body-text relation is needed.

The representation version is bound to the actual safe input fingerprint, source SHA, model and preprocessing version. An explicit correction or a change in the validity window rejects stale representations even if the note bytes have not changed; a policy change during encoding cannot publish the old generation. Unchanged replays do not re-encode; lost derived rows can be recovered by reusing existing vectors. When representations are unavailable, do knowledge_sync within the authorized scope; do not expand the scope because of a miss.

## Forming answers from evidence

Per the user's question, distinguish necessary facts, necessary conditions and supplementary examples, then choose citations that actually support each specific assertion; do not automatically list all returned context as citations. Source labels, title relevance, range verification or a sufficient evidence budget do not prove semantic support. Unrelated version differences and other acceptance tasks do not automatically become required parts of this answer. Leave missing current private project facts explicitly blank; general methods can be answered after stating their applicability scope.

Citation identity differs by kind: for ordinary Markdown evidence, source_sha256 and range bind the file; for kind=source, source_key=message:session:event, source_sha256 and range bind the specific message version, and path is only the projection entry point. Message ranges cannot be used as Markdown offsets, and a file SHA cannot replace a message version. Keep role, event time, completion/truncation and basis_status; cite only fragments actually received; do not fabricate ranges from adjacent messages, full source files or memory. A frozen evaluation's as_of is not the current time, and "this round" in historical reports does not automatically become current verification.

Each scope is still 1–12 exact paths/folder prefixes; background reconciliation of multiple registered notes is batched by exact path and shares a bounded encoding budget. knowledge_sync's complete/incomplete_notes distinguish current representation ready, pending, lease running, retrying and failed; changed/embedded being 0 is not by itself proof of readiness. Source noise is filtered by full source range; cross-chunk source lines cannot be handled using only the visible line starts of sub-chunks. Semantic representations are still derived candidates, not acceptance of source completeness or answer correctness.

Multi-ID `evidence` packs within the same budget by source identity, version and source range; overlaps between parent chunks and other hits do not take up space twice. It returns packing/evidence_chars/deduplicated_chars; independent messages with identical text are not removed by text similarity. Fragments keep exact ranges; part of the source text may be listed as context, so read text and context together. When an insufficient budget keeps conditions out, mark partial-budget; when a complete registered correction quote does not fit, report requires_context/not_current_basis in incomplete, and do not take its first sentence as reconfirmation. Single-ID behavior and the scope/source SHA/current-historical gates are kept; do not call the interface with a remaining budget below 500 characters.
