# 笔记与项目整理

保留迁移前的范围、整理和验收约定；普通召回不预读本文件。历史回查的具体工具路由见 [history.md](history.md)。

- 先读库级及目标目录适用的 AGENTS.md。用户已给出目录、材料或操作范围时直接使用，不重复询问。
- 根据任务只定位必要笔记。先查文件名和索引，再用 rg 搜索相关内容，读取指定页及确实需要的关联段落；不要默认全文加载整个库。
- 区分“只读检查”“建议/计划”与“执行整理”。前两者不写文件；明确要求执行后连续完成普通安全读写，不在每个阶段等待“继续”。
- 写前查看已有笔记并比较内容。优先增量更新原页，不重复创建同一项目、同一日记或第二份相同知识。同名冲突保留原文件，选择清楚命名的新稿或提出合并。
- 修改范围较大或批量处理时，先把原文件和清单备份到库外相邻位置，不跟随库外链接。写入前再核对原文件是否变化；并发变化先比较，避免丢失新内容。

## 记录约定

事实、决定、个人理解与 AI 建议分开。不推断经历、承诺、当前状态、截止日期或成果；未知属性留空或省略。用户确认“下一步”不等于确认 status 为 active。

项目记录直接写成果、决定与具体缺口，出处放文末。聊天是证据之一，不作为后续更新的前置条件；新的事实、用户说明或指定材料到来后更新原页。执行过程与技术验收写入 `95 AI 工作区` 已有相关记录，不在每篇正文重复统一声明，不为每个小修创建新日志。

原始资料不改写。基于资料提出的解释、知识候选和未经审阅的理解进入 `00 收件箱/AI 草稿`，标明待审，保留出处，不写成用户观点。用户明确要求分类处理事务时，已确认事实可直接更新正式项目、日记与阶段记录，无需把所有结果再次留成草稿。

保留原有 YAML 未知字段、双链、附件路径与来源定位。属性只加任务需要的字段，tags 用列表。日期规则：

- 每日笔记：`50 日记/每日/YYYY-MM-DD.md`，文件名代表实际事件日期。
- 每周复盘：`50 日记/每周/周一日期 周复盘.md`，周一至周日；未结束的周标明记录到哪天。
- created 是实际建笔记日期，updated 是有依据的修改日期；补录不伪造过去已写日记。没有依据时省略可选日期。
- 本周与下周重点由用户确认，最多三项；不倒填历史计划，不从过去日期制造逾期。
- 跨周期汇总按现有约定放入 `90 归档`；`50 日记` 根目录保留导航。

## 按目标工作

### 事务整理与项目更新

从用户指定的聊天、文件或说明提取实际发生的成果、决定、卡点及未完成项，按事件日期入每日记录，再汇总到相应周复盘。既有项目优先更新，已结束的阶段进入已有归档；归档阶段不等于整个项目完成。

status、next_action 和已确认 deadline 仅在项目页维护，索引只链接，首页通过视图展示。明确下一步写入 next_action；需要用户决定的内容留在待确认页。暂停项目保持原状态，除非用户明确改变决定；不要因此启动工程、实验或远程作业。

### 资料整理与知识草稿

只处理选定材料。资料页保留真实原文入口、作者/日期等有依据的元数据；摘录、转述与解释分别呈现。本地大文件先记录位置，不默认复制工程源码、完整数据集或全部 PDF。

知识围绕一个清楚的问题，写依据、方法或解释、适用边界与来源。默认情况下，证据充分且没有重要未解冲突的可复用知识可以自动写入 `30 知识`；记录为自动归纳，不伪造用户已审阅。其余有价值但缺证据的内容进入候选，说明推动转正的条件。示意例子标明用途，不冒充真实项目实现；未实际阅读来源不生成文章。细节见 [lifecycle.md](lifecycle.md)。

### 周期回顾

优先读取选定周期的每日笔记与必要项目记录，归纳成果、未推进原因与取舍；聊天用于补证据，按实际日期整理后再汇总。保留已存在的周复盘并增量补充，不把来源索引当作总结正文。

明确区分已有决定与建议。未获确认的重点仅作为候选列出，不写成正式任务。阶段归档和合并先列范围；删除、批量移动/改名或重构须有具体计划和用户确认，已有对应授权时不重复询问。

### 库内检查

仅检查指定目录或笔记的重复主题、文件/标题断链、属性冲突、陈旧导航及来源缺口。不要把模板代码块中的示意链接当成断链。预设待建链接与确认失效的链接分别报告；未经请求不自动修复。

修改 .base 时核对当前官方语法和实际字段，保留既有筛选与未知配置。未知状态、AI 草稿和示例不得混入真实活跃项目视图；不虚构完成率。文件解析与筛选核对不等于应用内渲染验证。

## 工具选择

普通笔记使用本地文件工具。Obsidian Markdown 或 Bases 格式复杂时，按需读取已安装的 obsidian-markdown / obsidian-bases skill；现有库规则决定属性与内容，不照搬上游示例中的项目状态和日期。

- Zotero：仅查指定主题或条目；默认只读，不索引整库或自动导入附件。
- 历史来源：按 [history.md](history.md) 使用原生历史分页与库内佐证；来源和执行边界保持不变。
- 公开文档检索：只发送公开技术问题，不发送私人笔记、未公开代码或凭据。
- Obsidian API/MCP：只在明确需要当前文件、应用搜索、打开笔记或命令时使用；先确认本轮允许的操作，不因接口存在扩大范围。
- 不自行安装/配置服务、开启同步、上传材料或发送消息。不读写 .obsidian，除非当前请求明确涉及该设置范围。

## 完成与交付

检查修改后的 UTF-8、YAML、核心文件/标题链接、日期与目标路径。可用现有轻量工具，不为验收安装新工具链；重复执行相同输入应跳过已记录事项。

交付具体新增/修改/跳过/冲突清单、主要差异、备份路径与恢复方式。区分文件校验、工具真实调用和应用界面验证；未完成的部分具体说明，不声称未进行的验证已通过。

技能文件和 AGENTS.md 都是行为指引，不是安全隔离。遵循当前用户授权，不修改或读取无关私人数据。

## 可直接调用

调用 OriMem 技能时可这样描述任务：

- 只读检查指定目录，列出重复主题、断链和属性冲突，不修改。
- 把本轮已确认的结果写入今天日记，增量更新指定项目页，来源放文末。
- 整理指定资料为一份 AI 草稿，保留出处，等我审阅。
- 汇总指定周的每日记录，更新周复盘，重点只列候选，归档先列范围。

来源佐证放 `90 归档/Codex佐证`，按事件月份定位；AI草稿仅保留实际的知识候选和待整理解释。目录迁移、删除或批量重构须有对应范围的明确授权；已确认的同一范围不重复询问。不要把“来源已归档／已索引”写成“知识已完成归纳”。

知识索引按稳定问题主题和阅读路径组织，阶段/批次说明归入 `95 AI 工作区` 已有实施记录，不继续在知识导航无限追加历史批次。只因主题或向量相近不能合并；requires/complements/contrasts 等联系要写出具体配合或区别。项目/课程/长期领域的方法参考不等于已采用。

拆分已登记主张时保留原段落到目标段落、源SHA和精确引文区间的映射。先通过同一 writer 写目标正文与原页的归位说明，再用 revise_assessment 绑定同收据，逐项 retirements 旧依赖并核对当前索引；不直接修改依赖SQL，也不删除原始佐证。未核对的段落继续保留，不用小标题分组冒充混题拆分完成。

日常 writer 的范围不自动扩大到 `20 长期领域`；普通 MCP/自动记录接口拒绝领域写入。领域或其它目录的维护需依据届时的明确授权另行实施，仍使用原哈希、备份、回读和收据。
